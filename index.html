02 / 协作闭环

每批任务怎样交到下一位手中

按序交接，审核不通过与上线缺陷都有返回路径。

从任务提出到下一轮排期
  1. 乙方01

    提出任务

    列明依据、对象、交付标准和建议排期。

  2. 双方02

    确认任务

    确定优先级、执行人、审核人和截止日。

  3. 甲方03

    补齐输入

    提供事实、证据、权限及必要开发资源。

  4. 乙方04

    制作与实施

    研究核验、制作内容，完成约定改动。

  5. 甲方05

    集中审核

    汇总事实、品牌及技术意见；需修改进06，通过后进07。

  6. 乙方 / 甲方06

    修订与补证

    乙方修订，甲方补证；返回05重新审核。

  7. 甲方批准人07

    书面批准

    生产变更前审核备份、变更及回滚资料。

  8. 已确认执行人08

    按权限上线

    由任务指定人员发布，留下URL及变更记录。

  9. 乙方09

    回读与监测

    检查上线结果、技术状态及AI表现。

  10. 双方10

    复盘再排期

    确认结果、遗留问题和下一轮任务。

审核需要修改 / 补证05 集中审核 → 06 修订与补证 → 返回05审核，通过后进入07。
上线检查发现缺陷09 回读与监测 → 返回修订、审核及批准流程 → 重新上线并回读。
↶复盘完成后，将观察结果与业务变化转为下一批任务。回到任务提出
一条任务记录，贯穿整个闭环对象 / URL / SKU、范围版本、交付标准、执行人、审核人、批准人、截止日、依赖资料、当前状态与结果证据。状态依次记录：待资料 → 制作中 → 待审核 → 修改中 → 待批准 → 待上线 → 已上线待验证 → 已验证；发现缺陷重新打开任务。

制作、录入、页面修改、技术开发、批准、发布、回读和回滚分别指定责任与权限。乙方承担分派给自己的后台/主题整改；甲方或其技术伙伴承接分派给自己的开发与批量更新。

监测、技术、商品事实和外部信源贯穿M1—M6。

监测 → 反馈 → 决策 → 执行

乙方监测与巡检 → 甲方补充业务变化 → 双方策略会确认优先级 → 执行批次闭环 → 乙方月报记录结果 → 进入下月。

每月重点SKU事实更新核验事实变化、维护补证与核验台账确认型号、参数、认证及政策；更新受影响页面事实资产、核验结论与页面修复状态
每月外部信源规划更新更新10个优先媒体/测评来源机会、2个传播选题及行动清单品牌/PR推进联络、采购、样机及实际发布来源机会、选题、成稿及发布链接分别记录

05 / 范围与验收

按独立清单验收，完成资产接管

美国市场 · 英文 · garvee.com。各类交付分别计数。

10个一级类目与几千条SKU，分层执行

10个一级类目全部做机会评估
最多4条从10条中选出的深度优先线
最多12个重点产品族
最多20个代表SPU
最多4,000条优先线内，冻结清单逐ID核验
12篇完整英文新内容
12个现有唯一URL优化
12个关键页面扫描
最多12项高优先级技术整改

数量边界：10个一级类目全部做机会评估；最多4条优先线完整诊断、实施与复测。12个产品族、20个代表SPU及最多4,000条SKU均在优先线内，20个SPU的深度研究不替代SKU逐条核验。经月度确认的最多2篇外部完整稿计入12篇新内容总量；4,000条SKU核验不等于4,000个页面代改。启动时确认逐ID核验字段、证据、人工复核边界、补证与修复责任。

终期验收闭环

乙方备齐材料 → 甲方分专业验收 → 乙方整改 → 甲方复验 → 确认验收记录 → 按约定条件结算及交接 → 甲方接管维护

必需材料不齐，验收期不开始；材料收到不自动等于实质质量合格。复验仍有缺陷，返回整改与复验环节。

接管资产：可编辑内容、事实资产、来源索引、代码/配置、实施及回滚资料、原始监测与数据核验记录、月报与阶段报告、未完成事项清单。

持续协作总量：6份月报、6次技术巡检、6次策略会、12次进度沟通、第90/180天两次阶段复盘。

可选免费延期：一次，最长1个月

符合条款条件且甲方选择时，另行确认截止日。延期至少提供1篇新内容、2个现有页面优化、1轮技术复查与修复清单、数据核验和月报，维持相同审核闭环；延期最低成果不能替代原期欠交。

计划依据：1023版待签合同修订稿及附件。实际日期、人员、权限、逐项责任与批次排期以双方确认记录为准。
